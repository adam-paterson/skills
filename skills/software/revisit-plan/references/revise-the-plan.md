# Workflow - Revise the plan

### 1. Review every open ticket

Read each ticket's question, type, blockers, and assignee, including claimed tickets. Compare them with the goal and decisions already made.

### 2. Propose changes and wait

List each proposed change and its reason. Identify tickets that another worker owns. Wait for the user's approval before editing the plan or tickets.

### 3. Apply the approved changes

Recheck affected tickets for changes made since the review. If those changes invalidate the proposal, ask before proceeding.

- Create new tickets first, then add their dependencies once their identifiers exist.
- Update questions that need clarification.
- Change ordering or priority to reflect what should happen next.
- Use dependencies only for actual prerequisites. Use the tracker's deferred status or backlog for work postponed by choice.
- Close excluded tickets and record why they fall outside the goal.
- Close duplicates or mistakes with a cancellation reason, and link the surviving ticket where applicable.

For claimed tickets, leave their state unchanged and comment with the approved proposal so the owner can coordinate the change. Report these edits as pending rather than applied.

Comment on every ticket changed, explaining what changed and why. Update the plan's summaries and scope to match. Report the applied changes and any pending coordination.
